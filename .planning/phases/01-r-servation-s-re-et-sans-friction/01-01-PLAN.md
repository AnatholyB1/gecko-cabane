From src/utils/supabase/server.ts (existing, do not modify in this plan):
- `export async function createClient()` -> cookie-bound Supabase server client
- `export async function isGeckoAdmin(supabase: Awaited<ReturnType<typeof createClient>>): Promise<boolean>` (rpc 'gecko_is_admin', false on error)

New contract created by this plan (consumed by plan 01-06):
- `src/utils/auth.ts`: `export async function requireAdmin(): Promise<{ ok: true; supabase: Awaited<ReturnType<typeof createClient>>; user: User } | { ok: false; response: NextResponse }>`
  - no user -> `{ ok: false, response: NextResponse.json({ error: 'Unauthorized' }, { status: 401 }) }`
  - user but not gecko admin -> `{ ok: false, response: NextResponse.json({ error: 'Forbidden' }, { status: 403 }) }`
  - usage in handlers: `const auth = await requireAdmin(); if (!auth.ok) return auth.response; const { supabase } = auth`

Current guard to replace (28 occurrences / 15 files incl. reservations; this plan does 14 files, 25 occurrences):
`const supabase = await createClient(); const { data: { user } } = await supabase.auth.getUser(); if (!user) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /api/* admin routes | Any account of the shared Supabase auth pool can send authenticated requests |
| route handler -> Supabase (cookie client) | RLS via gecko_is_admin() is the second layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Elevation of privilege | 14 admin route files | mitigate | requireAdmin() (getUser + gecko_is_admin RPC) on every POST/PUT/PATCH/DELETE; scan test blocks regressions at build (build runs vitest) |
| T-01-02 | Information disclosure | GET /api/tables/assignments | mitigate | requireAdmin() on GET (returns reservation names/phones) |
| T-01-03 | Information disclosure | error responses | mitigate | generic 'Internal server error', detail to Sentry |
| T-01-04 | Elevation of privilege | isGeckoAdmin RPC failure | accept | isGeckoAdmin returns false on RPC error -> fail-closed 403 (safe default) |
| T-01-05 | Spoofing | open signup /api/auth/signup | accept | out of phase scope; accounts without gecko_admins membership now get 403 everywhere |
</threat_model>
