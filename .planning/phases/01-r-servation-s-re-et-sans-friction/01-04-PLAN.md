- `type HoursRow = { is_open: boolean | null; open_time: string | null; close_time: string | null }`
- `resolveHours(date, regular: (HoursRow & { day_of_week: number })[], special: (HoursRow & { date: string })[]): HoursRow | null` (special wins)
- `type SettingsMap = Record<string, string | undefined>`
- `computeLastBookableMinutes(settings: SettingsMap): number` -> toMinutes(settings.last_reservation_time) if valid HH:MM, else toMinutes(KITCHEN_CLOSE) - (int(settings.table_block_duration_minutes) || DEFAULT_BLOCK_MINUTES)
- `bookableSlots(settings: SettingsMap): string[]` -> TIME_SLOTS filtered by <= computeLastBookableMinutes (used by the form)
- `checkSlot(input: { date: string; time: string; partySize: number; regular; special; settings: SettingsMap; now?: Date }): { ok: true } | { ok: false; code: 'slot_unavailable' | 'date_past' | 'invalid_party_size' }`
  Rules in order: partySize int 1..40 else invalid_party_size; date < bangkok today -> date_past; date > today + 180 days -> slot_unavailable; time not in TIME_SLOTS -> slot_unavailable; hours = resolveHours; closed/null -> slot_unavailable; t < open or t > min(close_time, lastBookable) -> slot_unavailable; same day and t < now.minutes + 30 -> date_past.

src/utils/validation.ts (rewritten phone helpers, keep existing banner/JSDoc style):
- `parsePhone(raw: string, country?: CountryCode): string | null` (libphonenumber-js/min parsePhoneNumberFromString + isValid -> .number)
- `normalizePhone(raw: string, country: CountryCode = 'TH'): string` -> parsePhone(...) ?? raw.trim() (back-compat string return)
- `isE164Phone(phone: string): boolean` -> starts with '+' and parsePhone(phone) === phone
- `phoneCountryForLocale(locale: string): CountryCode` -> 'fr'->'FR', 'en'->'GB', else 'TH'
- `isPartySizeValid` max 40 (uses MAX_PARTY_SIZE); `isReservationDateValid` compares against bangkokNow().date; `validateReservationFields` also requires customer_email (French message, returns string | null)
- `isEmailValid(email: string): boolean`

src/utils/reservation-schema.ts:
- `MARKETING_CONSENT_VERSION = 'reservation-form-2026-10-16'` (server-side only, never from client)
- `type ReservationErrorCode = 'invalid_body' | 'invalid_fields' | 'invalid_email' | 'invalid_phone' | 'invalid_party_size' | 'date_past' | 'slot_unavailable' | 'slot_full' | 'rate_limited' | 'too_fast' | 'server_error'`
- `reservationRequestSchema` (zod v4) fields: customer_name trim 2..100; customer_email trim lowercase email max 254; customer_phone trim 5..30; phone_country 2-letter uppercase optional; reservation_date /^\d{4}-\d{2}-\d{2}$/; reservation_time /^([01]\d|2[0-3]):[0-5]\d$/; party_size int 1..40 (z.coerce not allowed: must be number); occasion trim max 100 optional nullable; locale enum ['fr','en'] default 'fr'; marketing_consent boolean default false; website string max 200 optional (honeypot, checked in 01-08); form_started_at number int optional (checked in 01-08). Then a transform that sets customer_phone = parsePhone(customer_phone, phone_country ?? phoneCountryForLocale(locale)) and adds a zod issue with message 'invalid_phone' when null.
- `export type ReservationRequest = z.output<typeof reservationRequestSchema>`
- `export function firstErrorCode(error: z.ZodError): ReservationErrorCode` mapping: path customer_email -> invalid_email, customer_phone -> invalid_phone, party_size -> invalid_party_size, else invalid_fields
