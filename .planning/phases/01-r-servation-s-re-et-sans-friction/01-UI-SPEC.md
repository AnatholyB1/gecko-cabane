# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: (1) simplified `ReservationForm`, (2) floating WhatsApp button, (3) minimal `/privacy` page FR/EN.
> Auto mode: every value derives from CONTEXT.md (D-01..D-16), `src/components/ReservationForm.tsx`, `src/app/globals.css`, CLAUDE.md. No questions asked.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no `components.json`; shadcn explicitly out of scope, existing hand-rolled Tailwind v4 system is kept) |
| Preset | not applicable |
| Component library | none (native `<select>`, `<input>`, `<button>`) |
| Icon library | none installed; use inline SVG (WhatsApp glyph, spinner = existing `animate-spin` border pattern). Do not add a dependency. |
| Font | Cinzel (`font-cinzel`: headings, buttons), Cormorant Garamond (`font-cormorant`: body, inputs), Raleway (`font-raleway`: uppercase labels). Loaded in `src/app/layout.tsx`; Cinzel Decorative not used this phase. |

Tokens come from `src/app/globals.css` (`--gc-*` and `@theme inline` colors `gc-*`). Use `bg-gc-jungle`, `text-gc-text-dark`, etc. Legacy tokens (`--primary`, `--warm-gold`, ...) are admin-only: do NOT use them on public components. Tailwind v4 syntax only: `bg-(--gc-jungle)`, never `bg-[var(--gc-jungle)]`.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, gap between label and hint |
| sm | 8px | Label-to-input (`space-y-2`), stacked hints, consent checkbox-to-text gap |
| md | 16px | Error banner padding (`p-4`), default element spacing |
| lg | 24px | Form field gaps (`gap-6`, `space-y-6`) |
| xl | 32px | Card padding mobile (`p-8`), WhatsApp button edge offset on desktop |
| 2xl | 48px | Section breaks on /privacy between headings |
| 3xl | 64px | /privacy top/bottom page padding |

Exceptions:
- WhatsApp button: 56px x 56px (D-16), a multiple of 4.
- Touch targets: party-size +/- buttons raised from 36px to 44px (`w-11 h-11`); consent checkbox hit area 44px high via label padding (visual box 20px / `w-5 h-5`); country select and all inputs min height 44px.
- WhatsApp offsets: `bottom-4 right-4` (16px) below `sm`, `bottom-8 right-8` (32px) from `sm` up.

## Typography

Exactly 4 sizes and 2 weights for everything new or touched in this phase. Existing off-scale sizes in the form (12, 13, 15, 16, 18, 22) are consolidated onto this scale when the file is edited.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (inputs, paragraphs, banners, /privacy text) | 17px Cormorant | 400 | 1.5 |
| Label (field labels, uppercase, tracking 0.2em; button text Cinzel, tracking 0.1em) | 11px Raleway / Cinzel | 500 | 1.5 |
| Small (hints, inline errors, consent text, WhatsApp hover label) | 14px Cormorant italic for hints/errors, upright for consent | 400 | 1.5 |
| Heading (success title, /privacy h2) | 20px Cinzel | 400 | 1.2 |

Notes:
- The /privacy page title uses 20px Cinzel with `tracking-wide` plus a 40px gold rule (`w-10 h-px bg-gc-gold`) above it, consistent with the form's success state. No Display size is introduced.
- Weights: 400 (regular) and 500 (medium) only. Remove `font-bold`/`<strong>` emphasis from new code (phone echo in OTP block is deleted anyway).
- Body text on parchment/ivory: `text-gc-text-dark`; secondary: `text-gc-text-mid`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--gc-void` #0D1F17 | Page background (body), /privacy page background |
| Secondary (30%) | `--gc-parchment` #F5EEDA (card) with `--gc-ivory` #FAF0E6 (select backgrounds), border `--gc-aged` #E8DCC8 | Reservation card, /privacy content panel |
| Accent (10%) | `--gc-jungle` #0C3C2D (action) and `--gc-gold` #C69B3C (decoration) | See reserved list |
| Destructive / error | `--gc-copper` #8C5A3C | Inline errors, 429/validation banner border (`border-gc-copper`, `bg-gc-copper/10`), invalid field underline |
| Brand exception | WhatsApp #128C7E, hover #0B6B5F, glyph #FFFFFF | Floating WhatsApp button only |

Accent reserved for:
1. Submit button fill (`bg-gc-jungle`, hover `bg-gc-void`)
2. Focus underline / ring on inputs (`focus:border-gc-jungle`, `focus:ring-gc-jungle/25`) and valid-phone underline
3. Checked state of the marketing consent checkbox (`accent-gc-jungle`)
4. Gold corner ornaments on the form card and the gold rule above /privacy title
5. Links inside /privacy and the consent label (`text-gc-jungle underline`, hover `text-gc-void`)

Rules:
- Never use gold or jungle for error text. Errors use copper only.
- WhatsApp green is NOT the accent and must not appear anywhere else. Contrast: white glyph on #128C7E is about 4.2:1 (meets 3:1 for graphical objects); the stock #25D366 (about 2:1 with white) is rejected for accessibility. This is the "WhatsApp green" referenced in D-16.
- Copper #8C5A3C on parchment is about 5:1 (passes AA for 14px text).
- Placeholders stay `text-gc-text-mid/45` (decorative only; never carry required info).

## Component Contracts

### 1. ReservationForm (`src/components/ReservationForm.tsx`)

Removed (D-01/D-02): `PhoneVerifState`, `sendOtp`, `checkOtp`, `resetVerification`, OTP block, "Send code" / "Verified" buttons, `phone_verification_token`, `otpRequired` hint under submit, `disabled` coupling of submit to verification. Delete the related `otp*` keys from `messages/fr.json` and `messages/en.json` (parity test must still pass).

Layout (single column on mobile, `md:grid-cols-2` as today). Field order:
1. Full name (col 1)
2. Phone (col 2)
3. Email (full width, `md:col-span-2`) — now `required`, label gets the same required marker as other fields, `type="email"`, `inputMode="email"`, `autoComplete="email"`
4. Date, Time, Party size, Occasion (unchanged)
5. Marketing consent checkbox (full width)
6. Submit
7. Required-fields note, then privacy note

Phone field (D-05):
- Country selector: keep the `<select class="gc-select-light">` of `COUNTRIES` above the number input, preselected by locale: `fr` -> FR (+33), `en` -> GB (+44); fallback TH. Preselection happens from `useLocale()`, not hard-coded TH.
- Keep dial-code badge + local number input row; remove the action button, so the input is `flex-1` full width.
- Validation: inline, live, using `isValidPhoneNumber`. Invalid and non-empty: underline `border-gc-copper` plus hint `phoneInvalid` below (14px italic copper). Valid: underline `border-gc-jungle`. Do not block typing; block submit via native `required` + disabled state only while `loading`.
- `aria-invalid` and `aria-describedby` wiring on phone and email inputs to their hint ids.

Email field: invalid format shows `emailInvalid` hint after blur (not while typing); same copper treatment.

Party size: stepper keeps 1..40 (D-04 server cap is 40; client max raised from 20 to 40). `largeGroupWarning` (copper italic) stays for > 10 and its text must point to WhatsApp for groups. +/- buttons 44px; `aria-label` from i18n (`partySizeDecrease` / `partySizeIncrease`), not "-1"/"+1".

Honeypot (D-09):
- One extra text input named `website`, `tabIndex={-1}`, `autoComplete="off"`, `aria-hidden="true"`, wrapped in a div positioned off-screen (`absolute -left-[9999px] h-px w-px overflow-hidden`). Never `display:none`/`hidden`. No label text visible to assistive tech (the wrapper is `aria-hidden`).
- Sent as `website` in the POST body; server rejects non-empty (respond with a generic success-looking 200 or 400 per server plan; UI treats any non-ok as the generic error).
- A hidden `form_started_at` timestamp (ms, set in `useState` initializer or on first input) is sent for the minimum-fill-time check. No visible UI.

Marketing consent checkbox (D-11/D-12):
- Native `<input type="checkbox" id="res-consent">`, `defaultChecked={false}` always, `accent-gc-jungle`, 20px box, label wraps with 44px min tap height, gap 8px (`gap-2`), text 14px Cormorant upright `text-gc-text-dark`.
- NOT required and NOT pre-checked. Unchecked state is the valid default and submits `marketing_consent: false`.
- Label contains the `/privacy` link as a locale-aware link (`Link` from `@/i18n/navigation`), `target="_blank"` `rel="noopener"`, underline jungle, with visible focus ring. Link click must not toggle the checkbox (stop propagation on the anchor).
- Reset to unchecked after a successful submit.

Submit button: unchanged style (`primaryButtonClass`, full width, `py-4`, min height 48px). Enabled whenever not `loading`. Loading state: spinner + `sending` label, `aria-busy="true"`. Label `submit`.

States:

| State | Behaviour |
|-------|-----------|
| Idle | All fields editable, submit enabled |
| Field invalid | Copper underline + hint (phone live, email on blur) |
| Loading | Submit disabled, spinner + "Envoi en cours..." / "Sending...", inputs stay enabled but form ignores re-submit |
| Success | Replace form with existing success panel (gold rule, title, message, note, "new reservation" button). Message must state a confirmation email follows once the restaurant confirms (D-03). Focus moves to the success heading (`tabIndex={-1}`, `.focus()`), container `role="status"` |
| Server error 400/409/422 | Banner above the form with the server `error` message (translated key if code known, else generic), `role="alert"` |
| Error 429 (D-08) | Banner (copper) with `rateLimited` message plus a WhatsApp link button inside the banner; no auto-retry; submit re-enabled |
| Network error | Banner `networkError`, submit re-enabled |

429 banner layout: `border-l-2 border-gc-copper bg-gc-copper/10 p-4`, message 17px, below it an inline link "Écrire sur WhatsApp" / "Message us on WhatsApp" (underline, `text-gc-jungle`, 44px tap height) opening the same prefilled `wa.me` URL as the floating button. The banner is `role="alert"`; on error the page scrolls it into view (`scrollIntoView({ block: 'nearest' })`).

All error/validation strings that currently exist in French literal inside the component (`'Une erreur est survenue'`, `'Erreur de connexion...'`) move to next-intl keys.

### 2. WhatsAppButton (new, `src/components/WhatsAppButton.tsx`, client component)

Mounted once in `src/app/[locale]/layout.tsx` inside `NextIntlClientProvider`, after `{children}`. Never in `src/app/admin/`.

- Element: `<a href={waUrl} target="_blank" rel="noopener noreferrer">`, fixed position, `z-40`, `bottom-4 right-4 sm:bottom-8 sm:right-8`.
- Size: 56px circle (`w-14 h-14 rounded-full`), bg `#128C7E`, hover/focus `#0B6B5F`, white inline SVG glyph 28px, `shadow-lg`, transition 200ms.
- Define the two greens as CSS variables in `globals.css` (`--gc-whatsapp: #128C7E; --gc-whatsapp-dark: #0B6B5F;` plus `--color-gc-whatsapp*` in `@theme inline`) and use `bg-gc-whatsapp hover:bg-gc-whatsapp-dark`.
- URL: `https://wa.me/${process.env.NEXT_PUBLIC_WHATSAPP_NUMBER}?text=${encodeURIComponent(t('whatsapp.prefill'))}`; number env var is digits only (`66819585945`); component renders nothing if the var is missing. No tracking in this phase (deferred to phase 5).
- `aria-label`: `t('whatsapp.ariaLabel')`. Hover label: a pill to the left of the circle, visible on `hover` and `focus-visible` only at `md` and up (`hidden md:block`, opacity transition), bg `--gc-void`, text ivory 14px Cormorant, `px-4 py-2` (16/8), `whitespace-nowrap`, `pointer-events-none`. On touch/mobile no label.
- Focus: visible ring `focus-visible:ring-2 ring-gc-gold ring-offset-2 ring-offset-gc-void` (global 1px gold outline remains acceptable fallback).
- Mobile safety (D-16): the reservation form wrapper gets `pb-24` on `< sm` (page-level bottom padding of the reservation section) so the floating button never covers the submit button at scroll end; the button also hides itself (`opacity-0 pointer-events-none`) while the reservation submit button is within the viewport on mobile only if overlap would occur, implemented with an `IntersectionObserver` on `#reservation-submit` (add this id to the submit button). Below `sm`, overlap = hide; at `sm` and up never hide.
- Reduced motion: no pulse/bounce animation at all; only the opacity/colour transition (already neutralised by the global reduced-motion rule).
- Print/SSR: renders as a plain link (works without JS).

### 3. /privacy page (`src/app/[locale]/privacy/page.tsx`, Server Component)

- Route is localised (`/fr/privacy`, `/en/privacy`), text from `getTranslations('privacy')` in both JSON files; `generateMetadata` with translated title, `robots: index,follow`.
- Layout: full-height `bg-gc-void` page, content panel `max-w-2xl mx-auto bg-gc-parchment border border-gc-aged` with the same gold corner ornaments as the form card, padding 32px mobile / 48px `sm`+ (`p-8 sm:p-12`), page vertical padding 64px.
- Structure (each section: h2 20px Cinzel `text-gc-text-dark`, 16px gap, then 17px Cormorant paragraph(s) `text-gc-text-dark`, 48px between sections):
  1. Title (page h1 styled as Heading) + "Dernière mise à jour" / "Last updated" line (14px, `text-gc-text-mid`)
  2. Who we are (Gecko Cabane, Maharat Road, Krabi Town; contact phone +66 81 958 5945 and email)
  3. Data we collect (name, phone, email, reservation details, optional marketing consent with timestamp and source)
  4. Why (handle reservation; newsletter only if consent given)
  5. Legal basis and rights (PDPA B.E. 2562 and GDPR: access, rectification, erasure, withdraw consent)
  6. Retention and sharing (processors named by category: hosting, email delivery; no sale of data)
  7. How to unsubscribe / contact (email link; unsubscribe link in every newsletter)
  8. Back link "Retour à l'accueil" / "Back to home" (jungle underline, 44px tap)
- Body copy is drafted by Claude and flagged: a visible HTML comment is not allowed; instead add the flag in the plan as a blocking pre-launch checkpoint (owner validation, CONTEXT D-13). Do not render any "draft" text to visitors.
- Semantic markup: one `h1`, `h2` per section, `<main>`, lists as `<ul>` with 8px item gap. Max line length 65ch.
- Links: footer/legal link to `/privacy` is out of scope except the consent checkbox link and the page back link.

## Accessibility and Interaction Requirements

- Every input has a visible `<label htmlFor>`; the party-size group gets `role="group"` + `aria-labelledby`.
- Errors announced: banners `role="alert"`; field hints linked by `aria-describedby`.
- Keyboard order follows visual order; honeypot excluded (`tabIndex=-1`, `aria-hidden`).
- Minimum touch target 44px for all interactive elements added or modified.
- Focus-visible ring retained (global gold outline plus jungle ring on inputs).
- Respect `prefers-reduced-motion` (already global).
- Target: a visitor fills name, phone, email, date, time and sends in under 60 seconds on mobile; no step blocks the others (single page, no modal, no code entry).
- Responsive: single column below `md`; WhatsApp button and card tested at 360px width.
