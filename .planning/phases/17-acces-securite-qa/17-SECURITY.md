## Réponses aux questions de l'audit

**Jeton.** 32 octets `randomBytes` (256 bits, base64url 43 car.), seule l'empreinte SHA-256 stockée (`token_hash` unique, `check ~ '^[0-9a-f]{64}$'`). La comparaison est une égalité de hachage faite par la base : pas de comparaison de secret en clair, donc pas d'oracle temporel exploitable. Expiration `expires_at = now + 7 j` exactement (`INVITE_TTL_MS`, test), `claim` exige `expires_at > now` (strict) : à l'instant d'expiration le lien est mort. Usage unique : `UPDATE … WHERE used_at IS NULL AND revoked_at IS NULL AND expires_at > now RETURNING` (Postgres READ COMMITTED réévalue le prédicat après verrou : un seul des deux appels concurrents obtient la ligne ; le test de concurrence existe sur doubles). Ouvrir la page (GET) ne consomme rien. Rejeu : 410 uniforme, une seule phrase pour inconnu / expiré / utilisé / révoqué / mauvais type / mal formé (type vérifié : un jeton `invite` ne réinitialise pas). Fuites : `referrer: no-referrer`, `force-dynamic` (en-tête réel constaté : `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`), aucune ressource tierce, Plausible n'est monté que dans `[locale]/layout.tsx`. Reste le jeton dans l'URL pour Sentry (M1) et les journaux Vercel.

**Élévation de privilèges.** Seule la ligne `gecko_admins` donne l'accès ; elle n'est insérée que par `acceptInvitation` (service role, serveur) après claim du jeton. `gecko_admins` n'a que la politique « self read » : aucun utilisateur ne peut s'y inscrire. Un compte du portfolio qui reçoit une invitation obtient 409 sans droit et son mot de passe n'est jamais modifié. Routes `/api/access/*` (GET, invitations, DELETE admins/invitations) : sans session, 401 constaté ; avec session non admin, `requireAdmin` renvoie 403 (fail-closed sur erreur RPC). Auto-révocation refusée deux fois (route + SQL). Dernier admin : la fonction prend `lock table gecko_admins in share row exclusive mode` (auto-conflictuel, bloque aussi les `insert`) : deux admins qui se retirent mutuellement sont sérialisés, le second reçoit `last`. La réinitialisation vérifie l'appartenance à `gecko_admins` à la demande ET à l'usage, et `user_id` du jeton = `id` de la ligne.

**Énumération.** Connexion : un seul message pour identifiants faux, compte inconnu, non confirmé ; erreur Supabase jamais affichée, seul un code voyage (le code `noaccess` révèle seulement qu'un mot de passe valide existe, ce qui suppose de le connaître). Oubli : même JSON 200 pour admin / inconnu / portfolio ; le travail passe dans `after()` ; seuil par adresse neutre ; 429 par IP indépendant de l'existence. Invitation : n'interroge que `gecko_admins`, jamais le pool.

**CSRF.** Routes `/api/access/*` : `isSameOrigin` (Origin / Sec-Fetch-Site) + Content-Type JSON obligatoire + 4 Ko ; constaté : requête inter-sites 403, `text/plain` 400. Aucun GET mutant dans le module (le seul est le logout, voir tableau). Server action de connexion protégée par le contrôle d'origine de Next.

**Redirections.** `safe-redirect` : 27 charges testées (`//`, `/\`, `/%2f`, `/%2F%2F`, `/%5c`, `@`, schéma, tabulations, `%09`, `%0d%0a`, `///`, `javascript:`, UTF-8 invalide, `%252f`) toutes ramenées à `/admin` ; les chemins admin légitimes avec `?`/`#` restent intacts et internes. `/auth/callback` (`safeNextPath`) identique. Les URL de connexion ne portent que des codes (`e`, `m`).

**Email d'invitation.** `escapeHtml` sur l'adresse de l'invitant et le lien, `stripLineBreaks` sur le sujet, destinataire validé par regex sans espace ni `<>()[],;:"` : pas d'injection d'en-tête ni de HTML (sondes `a@b.co\r\nBcc:…`, `a@b.co,c@d.co`, `<x>@y.zz` refusées). Base du lien : `ACCESS_LINK_BASE_URL` (https ou localhost) ou `SITE_URL`, jamais un en-tête de la requête.

**Secrets.** `createAdminClient` n'est importé que par des routes / utilitaires serveur ; le formulaire client n'envoie que le jeton et les mots de passe en corps POST.

**Migration 020.** Supprime bien les 4 politiques « Public read » (noms identiques à 007:455-471) et le `SELECT` d'`anon` ; lecture publique effectivement fermée (RLS sans politique pour `anon`, et les non-admins `authenticated`, dont le portfolio, perdent aussi la lecture : c'est ce que vérifie `17b-ACC01-NOTES.md`). N'affaiblit rien : les politiques « Admin manage » et `gecko_is_admin()` (qui lit `gecko_admins`, pas ces tables) sont intactes ; aucune fonction SQL ne référence ces tables (grep : 007 et 020 seulement) ; aucun code `src/` ne les lit. Idempotente. Rollback correct (4 `create policy` + `grant select … to anon`). Reste le `grant select` d'`authenticated`, inoffensif sans politique.

**Migration 021.** RLS activée sans politique ; `revoke all … from public, anon, authenticated` ; seul `service_role` accède. `gecko_revoke_admin` : `security definer`, `search_path = public` fixé (voir tableau pour `pg_temp`), `execute` retiré de `public, anon, authenticated` et accordé à `service_role` seul ; retours `self` / `last` / `not_found` / `ok`. Index partiel : une seule invitation vivante par (type, adresse). Rollback manuel cohérent. Ne touche aucune table existante.

**17a.** Un non-admin ne peut ni fermer ni rouvrir : `requireAdmin` sur GET/POST/DELETE (401 constaté sans session ; test `admin-routes-guarded`). Écriture avec la session de l'administrateur (RLS), pas de service role. Dates : seules les dates calendaires réelles `AAAA-MM-JJ` d'aujourd'hui à +180 jours sont acceptées ; `2026-02-30`, `2026-11-01\n`, `2026-11-01'; drop`, `…T00:00`, `…%00`, `2027-06-01` rejetées (400) ; la clé mémoire `service_closure_prev:<date>` n'est construite qu'avec une date validée (pas d'injection). L'état précédent est restauré à l'identique par `parseMemory` strict (forme inattendue : suppression de la ligne de fermeture, état sûr) ; deux fermetures concurrentes écrivent la même mémoire (idempotent). Fuite de la mémoire par `/api/settings` : voir tableau.

**Formulaire public (`ReservationForm.tsx`).** Pas de régression i18n (aucune chaîne nouvelle, réutilise `slotUnavailable` ; vérifié dans le diff), le créneau soumis est `selectedTime` (reste dans la grille serveur, le serveur reste l'autorité via `checkSlot`), échec de `/api/hours` ou `/api/special-hours` : grille complète conservée (le serveur refuse). Accessibilité : `aria-describedby` + `role="status"` sur l'indication, mais elle s'affiche aussi quand la journée entière est fermée (message « créneau indisponible » acceptable). Pas de défaut.
