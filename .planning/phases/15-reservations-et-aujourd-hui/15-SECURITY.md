## Vérifications

1. **API figée : byte-identique.** `git diff c6bc779 HEAD -- src/app/api/reservations src/utils/resend*` : vide (aucun octet changé). Idem `src/app/api/cron/**` (dont `review-invitations`) et `src/app/api/kpi` : diff vide. Seuls écarts sous `src/app/api` depuis `c6bc779` : suppression de `auth/signup` et de `tables/**` (attendues) et `mcp/route.ts` (remplacement de `remaining >= party_size` par `hasCapacity(booked, party, max)` = `booked + party <= max`, sémantique équivalente, aucune PII). Écarts utilitaires : `manual-reservation.ts` (champ `allergies` additif et optionnel, absent ou vide donne une valeur identique à avant, longueur max 500, type string), `reservation-rules.ts` (ajout de `hasCapacity`), `review-badges.ts` (ajout de `tone`), nouveaux `krabi-time`, `phone-links`, `reservation-list`, `reservation-status`, `today`. La route `reservations/manual` n'a pas changé : elle construit l'insertion depuis le résultat de la liste blanche du validateur (pas de mass-assignment).
2. **Autorisation.** Toutes les routes de mutation admin (`announcement`, `hours`, `settings`, `special-hours`, `menu/*`, `kpi`, `review/stats`, `reservations` GET/PUT/DELETE, `reservations/manual`) appellent `requireAdmin()` (session + `gecko_is_admin` en échec fermé, 401/403). Les GET publics (`announcement`, `hours`, `special-hours`, `menu/*`, `settings`) ne renvoient pas de PII. Crons protégés par `CRON_SECRET` (`isAuthorized`), webhook Resend par signature Svix, `newsletter/*` et `review/*` publics par conception (jeton opaque). `GET /api/reservations` : admin uniquement, `select('*')` (PII et `review_token`) jamais servi à un non-admin. `SUPABASE_SERVICE_ROLE_KEY` : une seule occurrence, `src/utils/supabase/server.ts:46` (module serveur) ; aucun composant client n'importe `createAdminClient`. Les 17 usages de `createAdminClient` sont dans des routes serveur/crons/utilitaires serveur avec justification en commentaire (RLS sans policy publique : réservations, newsletter, consentements). La route MCP n'emploie le client admin que pour `party_size` (agrégat) et ne renvoie que menu/horaires/disponibilité.
3. **Liens `tel:` / WhatsApp.** `src/utils/phone-links.ts` : `toE164` refuse tout caractère hors `^\+?\d+$` après nettoyage, pas de pays par défaut, validation `libphonenumber` ; un numéro mal formé ou `javascript:...` donne `null` donc aucun lien rendu. Le `href` est reconstruit (`tel:+E164`, `https://wa.me/<chiffres>`), jamais la valeur brute. `ReservationRow.tsx:77-82` : WhatsApp en `target="_blank" rel="noopener noreferrer"` ; `tel:` en même onglet. Le seul élément envoyé au tiers (wa.me) est le numéro voulu ; aucun nom, email ni note dans l'URL. Le texte de partage d'avis (`ReviewsPanel`) est sans donnée client.
4. **Saisie manuelle.** Serveur (`validateManualReservation`) : nom 2-100, téléphone `parsePhone` <= 30, email <= 254 + regex, date réelle, heure `HH:MM`, couverts entiers 1-50, notes <= 2000, allergies string <= 500, source en liste blanche (sans `site`). Insertion via le client cookie : la RLS `gecko_is_admin()` s'applique (défense en profondeur). Affichage : tout est rendu en nœuds texte React (nom, allergies, occasion, notes, téléphone) ; aucun `dangerouslySetInnerHTML` / `innerHTML` sous `src/components/admin`. Les messages de confirmation (`actions.ts`) sont du texte, pas du HTML. PUT : liste blanche stricte (`status`, `admin_notes`, `source`), `id` entier > 0.
5. **Migration 019.** Additive : `alter table ... add column if not exists allergies text check (allergies is null or char_length(allergies) <= 500)`. Nullable, sans défaut ni rétro-remplissage. Aucune policy ajoutée ni modifiée, aucun `GRANT`. La table reste sans policy publique (007 ligne 13/443) et les droits par défaut sont révoqués (010) : la colonne n'est lisible que par `gecko_is_admin()`. `gecko_create_reservation` inchangée. Ordre de déploiement documenté (migration avant le code) ; non encore appliquée, dégradation propre (champ omis si vide).
6. **Suppression de `/api/tables`.** `src/app/api/tables`, `src/app/admin/tables` absents ; aucune référence résiduelle dans `src` à `gecko_table*`, `/api/tables`, `table_assignment` (garde-fou `tests/tables-removal.test.ts`, qui vérifie aussi que `gecko_create_reservation` ne lit pas `gecko_table*`). **Dette ACC-01 (documentée)** : les tables `gecko_tables`, `gecko_table_configurations`, `gecko_table_configuration_tables`, `gecko_table_assignments` restent en base avec RLS active ; `gecko_table_assignments` conserve une policy SELECT publique (baseline 007, en-tête lignes 11-12 : pas de PII, mais expose les blocages horaires par `reservation_id`), et les lectures publiques des tables de plan de salle subsistent. Aucune route de l'application n'y accède plus ; la fermeture se fait par une migration future (`drop policy` / `drop table`) soumise à l'accord du propriétaire.
7. **`/api/auth/signup` supprimé.** Route absente ; aucune référence dans `src` (`tests/signup-api-removal.test.ts`). `/admin/signup` n'est qu'une page statique d'information et `signupAction` redirige vers `/admin/signup` sans appeler Supabase : aucun contournement, aucun `auth.signUp` dans le dépôt applicatif.
