# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5 (Conversion et mesure). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Mode AUTO: every value is taken from 05-CONTEXT.md (locked decisions), 05-RESEARCH.md, and the existing `gc-*` design system in `src/app/globals.css` and `src/app/[locale]/page.tsx`. Nothing here introduces a new visual language.

- Map embed height 288px (`h-72`) mobile, 320px (`md:h-80`) desktop.

## Typography

Phase 5 declares four sizes and two weights, reusing the existing scale. Existing 11px eyebrow, 13px and 22px values elsewhere on the page are untouched; new surfaces use only the four below.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (Cormorant, reviews, descriptions, payment line, trajets) | 17px | 400 | 1.5 for short UI text (payment line, list items); 1.85 for long prose (about), matching existing `leading-[1.85]` |
| Label (Raleway eyebrows, captions, country/language tags, CTA buttons in Cinzel, form labels) | 12px | 400 (Raleway 300 light is the existing family weight for eyebrows; render as 400 token) | 1.5, uppercase, `tracking-[0.15em]` to `[0.3em]` |
| Heading (Cinzel h3: review rating, "Comment venir", "Un souci ?", admin h2) | 20px | 400 | 1.2 |
| Display (section `h2`) | `clamp(26px, 3.5vw, 42px)` | 400 | 1.2 (`leading-tight`) |

Weights: 400 (regular) and 600 (semibold) only. Semibold is used for the reviewer first name, the rating figure ("4,7") and owner/name emphasis (`font-semibold` span, same as existing `chef`/`seats` rich-text spans). Cinzel headings stay at 400 (existing `font-normal`).

Admin pages (French, fixed) use the existing admin page typography; do not introduce the public font stack changes there. Same four sizes, same two weights.

Review text rules: Cormorant italic 17px/1.5 for the quote body (italic is a style, not a weight). Never truncate with ellipsis in the contract; limit to the validated review length in `social-proof.ts`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `gc-parchment #F5EEDA` (light sections) and `gc-void #0D1F17` (page/body, footer, overlays) | Section backgrounds |

| Accent (10%) | `gc-gold #C69B3C` (on dark) / `gc-brass #B8860B` (on parchment, text-safe) | Reserved list below |
| Destructive | `#B91C1C` text / `#FEE2E2` background (existing form error treatment; reuse whatever `ReservationForm` already uses) | Error messages only. No destructive actions exist in this phase |

Accent reserved for (Phase 5):
1. Star glyphs and the rating figure in the social-proof badge
2. Travellers' Choice badge outline/icon
3. The `GcDivider` and eyebrow under section headings
4. 1px focus ring on all new interactive elements (`outline: 1px solid gc-gold`, existing global rule)

6. Review card top border (`border-top: 2px solid gc-gold`, same as `.gc-card-pilier`)

Accent is NOT used for: body text, review quote text, payment line, trajets list, link text in prose, admin table borders.

Semantic brand colors (outside the 60/30/10 split): `gc-line` green for the LINE floating button only; `gc-whatsapp` for the WhatsApp floating button only. Neither may appear anywhere else.

Contrast contract: body text on parchment uses `gc-text-mid`/`gc-text-dark` (>= 4.5:1); text on jungle/void uses `gc-ivory` at >= 75% opacity (ivory/65 is allowed for subtitle-size 17px only, as in the existing reservation subtitle). Do not use `gc-gold` as small text on parchment (use `gc-brass`).

## Surfaces

### 1. Social proof section (`SocialProof`, server component, immediately before `<section id="reservation">`)

Gating (D-11, Pitfall 9): `reviews: []` is a supported state. If no owner-validated review exists, render only the rating badge row (rating, stars, count, Travellers' Choice if verified) and the "Laisser un avis" link. If the rating config is also not validated, render nothing. Never render placeholder or lorem reviews.

Layout:
- `<section aria-labelledby="social-proof-title" class="py-24 px-6 bg-gc-parchment">` (no `id` anchor, no nav link). Boundary: the section above (#hours) is also parchment, so separate with a 1px `gc-aged` top border and rely on `py-24`; do not alternate to jungle (reservation follows and is jungle, so parchment here gives a clean transition into it).
- Header (centered): Raleway eyebrow ("Ils nous recommandent"), Cinzel `h2` display size, `GcDivider dark`.
- Badge row (centered, `flex flex-wrap items-center justify-center gap-6`): rating figure "4,7" (Cinzel 20px, the figure itself in a semibold span), 5 star SVGs (gc-brass fill, `aria-hidden`), text "sur 1 062 avis" (Cormorant 17px, gc-text-mid), and Travellers' Choice badge (bordered chip: `border border-gc-gold px-4 py-2 min-h-11`, Raleway 12px uppercase, small award SVG). The row has one accessible name: `aria-label` "Note 4,7 sur 5, 1 062 avis" (i18n).
- Review cards: `grid gap-6 md:grid-cols-2 lg:grid-cols-3` (3-4 reviews; 4 reviews wrap to 2x2 at `md`, 4 columns not used). A static grid, NOT a carousel (no JS, no CLS, no auto-advance; satisfies PageSpeed and a11y). Each card is a `<figure>`: `bg-gc-jungle`, `.gc-card-pilier`-style top border gold 2px, padding 24px (`p-6`), no hover lift (not interactive as a whole).
  - `<blockquote lang="{original lang}">` Cormorant italic 17px, `text-gc-ivory/90`, line-height 1.5, with `lang` attribute set to the review's original language (D-13).
  - `<figcaption>`: first name (semibold, gc-ivory), country (Raleway 12px uppercase, gc-gold/65 minimum on jungle; use `gc-celadon` if contrast check fails), language tag chip ("EN", "DE"; Raleway 12px, `border border-gc-gold/30 px-2`), and a source link ("Google" or "TripAdvisor") to the original review URL: `target="_blank" rel="noopener noreferrer"`, `min-h-11`, underlined on hover, `aria-label` "Voir l'avis de {name} sur {source}".
  - Stars per card: 5 gc-gold SVGs, `aria-hidden`, with sr-only "5 sur 5".
- Footer CTA (centered, mt-12): link "Laisser un avis" to `/review?src=site` styled as the existing outlined button (`font-cinzel text-[12px] tracking-[0.15em] uppercase border border-gc-text-dark text-gc-text-dark px-6 py-3 min-h-11 hover:bg-gc-text-dark hover:text-gc-parchment`). Internal navigation, same tab.
- Responsive: mobile single column, cards full width; badge row wraps; no horizontal scroll.
- Visual match for JSON-LD (D-14): the displayed rating "4,7" and count "1 062" are rendered from the same `SOCIAL_PROOF` constants as `aggregateRating` (single source of truth). Locale formatting of numbers via `Intl.NumberFormat(locale)`.

### 5. Floating contact stack (`FloatingContact`, RESA-05)

- One fixed container: `fixed z-40 bottom-4 right-4 sm:bottom-8 sm:right-8 flex flex-col gap-3 items-end` (LINE on top, WhatsApp below, exactly the order in D-22).
- Each button: `w-14 h-14` (56px) circle, `shadow-lg`, white glyph (28px SVG), `transition-[opacity,background-color] duration-200`, `focus-visible:ring-2 focus-visible:ring-gc-gold focus-visible:ring-offset-2 focus-visible:ring-offset-gc-void`. WhatsApp: `bg-gc-whatsapp hover:bg-gc-whatsapp-dark` (unchanged markup). LINE: `bg-gc-line hover:bg-gc-line-dark focus-visible:bg-gc-line-dark`, LINE speech-bubble glyph, white.
- Desktop (`md+`): the existing hover/focus tooltip pattern on the left of each button (`bg-gc-void text-gc-ivory`, keep the existing tooltip classes unchanged for WhatsApp and replicate them exactly for LINE so both are identical).
- Labels / a11y: `aria-label` from i18n `line.ariaLabel` ("Nous écrire sur LINE") and existing `whatsapp.ariaLabel`; both `target="_blank" rel="noopener noreferrer"`. Tab order: LINE then WhatsApp (DOM order matches visual top to bottom).
- LINE visibility: rendered ONLY if `getLineUrl()` returns a valid URL (D-22). Otherwise only WhatsApp renders, with no gap or placeholder. Never a dead or `#` link.
- Mobile hide logic: the existing IntersectionObserver on `#reservation-submit` (max-width 639px) is moved to the container; when hidden the whole container gets `opacity-0 pointer-events-none` and the links get `tabIndex={-1}` + `aria-hidden` while hidden. Two stacked buttons (56 + 12 + 56 = 124px) plus bottom offset 16px must not cover form fields; the form card keeps its `pb-24`.
- Click tracking: `onClick` fires `track(EVENTS.lineClick | EVENTS.whatsappClick, { locale })`; the handler never preventDefaults and never delays navigation.
- Reduced motion: transitions already collapsed globally.

### 6. "Un souci ?" form on `/review` (REV-07)

- Placement: on the `/review` page, in the same view as the Google/TripAdvisor buttons (D-23, no filtering), below them, separated by a gold hairline divider. The page keeps its existing dark/jungle styling and `max-w` column; reuse the page's existing wrapper classes.
- Structure (`ReviewFeedbackForm`, client): Cinzel h2 20px "Un souci ?", Cormorant 17px lead-in "Dites-le nous directement, nous lisons chaque message.", then a form:
  - `<label>` (Raleway 12px uppercase tracking-[0.15em], gc-gold/65 on dark) + `<textarea>`: required, `maxLength=1000`, `rows=5`, `min-h-32`, full width, `bg-transparent border border-gc-gold/30 text-gc-ivory font-cormorant text-[17px] p-4 focus:border-gc-gold`, live character counter "{n}/1000" (Raleway 12px, `aria-live="off"`; announces only when within 50 chars of limit via `aria-live="polite"` status).
  - `<label>` "Email (facultatif)" + `<input type="email" autocomplete="email">` same styling, `min-h-11`, helper text (Cormorant 17px, ivory/65): "Seulement si vous souhaitez une réponse."
  - Honeypot field (`company_url`): visually hidden via `sr-only`-style off-screen wrapper, `tabIndex={-1}`, `autoComplete="off"`, `aria-hidden="true"`; not a visible label.
  - Submit button: Cinzel 12px uppercase `tracking-[0.15em]`, `bg-gc-gold text-gc-void hover:bg-gc-brass px-8 py-3 min-h-11`, label "Envoyer le message" (EN "Send message"). Disabled + label "Envoi…" while pending.
- States:
  - Idle, pending (button disabled, `aria-busy` on form), success (replace form with a `role="status"` block: "Merci, message transmis."), error (inline `role="alert"` under the submit button, text color `#FCA5A5` on dark for contrast, never red-on-jungle), validation (field-level message, `aria-invalid`, `aria-describedby`), rate-limited 429 (message below).
  - Form stays visible and data is preserved on error.
- The success copy never claims a reply or a guaranteed delivery beyond "transmis" (Research Pattern 5).
- Page remains `noindex`, no personal data displayed, no tracking script events on this form.
