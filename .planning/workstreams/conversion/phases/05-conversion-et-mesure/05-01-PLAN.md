<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /gcm/* -> plausible.io | first-party proxy forwards visitor requests to a third party |
| URL query -> sessionStorage -> reservation POST | attacker-controlled utm/ref strings travel to the API |
| env var -> next.config rewrites | build-time value builds an external destination URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | next.config.ts rewrites destination | mitigate | script id must match /^pa-[A-Za-z0-9_-]+$/ before it is interpolated into https://plausible.io/js/<id>.js; otherwise no rewrite and no script (test-enforced) |
| T-05-02 | Tampering / Injection | utm_source, utm_medium, ref | mitigate | client bounds to 3 known keys and 100 chars; server allowlist regex + length check in 05-02; values are never rendered as HTML |
| T-05-03 | Information disclosure | Plausible pageviews of /review?rid=... | accept | Plausible stores the pathname and UTM params, not arbitrary query strings; rid is a random UUID, not personal data; no cookies (D-01) |
| T-05-04 | Information disclosure | event props | mitigate | props limited to locale and utm_source; no name, email or phone ever passed to track() (source-scan: track calls only in ReservationForm and FloatingContact) |
| T-05-05 | Denial of service | middleware on /gcm | mitigate | /gcm excluded from the matcher so events never trigger Supabase getUser or i18n redirects |
</threat_model>
