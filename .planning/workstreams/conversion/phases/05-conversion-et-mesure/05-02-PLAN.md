## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public client -> POST /api/reservations | untrusted body, may include forged source / hostile utm |
| admin browser -> PUT /api/reservations | authenticated admin, still validated |
| route -> Supabase (service role) | follow-up UTM update bypasses RLS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 | Tampering | reservation source on public POST | mitigate | schema has no source key (stripped), route never reads it, DB default 'site' + check constraint; forgery test in reservations-post.test.ts |
| T-05-07 | Tampering / Injection | utm_source, utm_medium, ref | mitigate | sanitizeUtm allowlist regex (1-100 chars of [A-Za-z0-9._~/-]) + DB char_length checks; rendered as React text in admin only |
| T-05-08 | Elevation of privilege | PUT source | mitigate | requireAdmin() unchanged + isReservationSource whitelist; no other column added to the whitelist |
| T-05-09 | Elevation of privilege | service-role UTM update | mitigate | update keyed by the id returned by the RPC in the same request, only the 3 sanitized columns; existing justification comment |
| T-05-10 | Denial of service | UTM update failure | mitigate | best effort in try/catch; booking response unchanged; Sentry captures without PII |
</threat_model>
