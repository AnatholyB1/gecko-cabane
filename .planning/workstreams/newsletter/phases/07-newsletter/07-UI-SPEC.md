# Phase 7 — UI Design Contract

> Visual and interaction contract for the Newsletter phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Sources: 07-CONTEXT.md (D-10..D-13, D-17), existing tokens in `src/app/globals.css`, patterns from `SiteFooter`, `WhatsAppButton`, `/[locale]/review/page.tsx`.

Surfaces covered: (1) footer sign-up, (2) exit-intent pop-up (desktop) / bottom sheet (mobile), (3) `/newsletter` (bill QR, crab curry recipe), (4) `/wifi`, (5) confirm page, (6) unsubscribe page, (7) transactional email templates (confirmation, welcome, unsubscribe footer).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Next.js 16 + Tailwind v4, hand-built components; shadcn gate not applicable: project has no `components.json` and an established bespoke brand system, do not introduce it) |
| Preset | not applicable |
| Component library | none (native elements + shared `NewsletterForm`) |
| Icon library | none; inline SVG only (as in `review/page.tsx`); `×` close glyph as inline SVG |
| Font | Cinzel (headings, buttons), Cormorant Garamond (body, default), Raleway (eyebrows/labels), via existing `font-cinzel`, `font-cormorant`, `font-raleway` classes. Cinzel Decorative not used in this phase. |

Reuse, do not re-specify: `bg-gc-*` tokens, `.focus-visible-ring`, global `input:focus-visible` gold outline, reduced-motion media query, `review` button classes (`buttonBase`, `primaryClass`, `secondaryClass`) which must be extracted to a shared module (`src/components/ui/buttonClasses.ts`) rather than copied.

Components to create:
- `NewsletterForm` (client): shared by footer, pop-up, `/newsletter`, `/wifi`. Props: `source` (`footer|popup|bill_qr|wifi`), `variant` (`dark|light`), `showResident` (bool).
- `NewsletterPopup` (client): mounted in `src/app/[locale]/layout.tsx`; renders nothing on `/review`, reservation funnel, admin.
- Pages: `[locale]/newsletter/page.tsx`, `[locale]/wifi/page.tsx`, `[locale]/newsletter/confirm/page.tsx`, `[locale]/newsletter/unsubscribe/page.tsx`. Short-URL alias routes `/newsletter` and `/wifi` follow the `/review` alias pattern (locale resolution without `/fr` redirect for English tourists).

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between label and input, inline icon gaps |
| sm | 8px | Gap between checkbox and consent text, sheet edge inset |
| md | 16px | Default field gap, card inner padding (mobile sheet) |
| lg | 24px | Pop-up and card inner padding (desktop), section padding |
| xl | 32px | Gaps between page blocks, `p-8` card padding |
| 2xl | 48px | Card padding `sm:p-12`, major section breaks |
| 3xl | 64px | Page top padding (`pt-16`) |

Exceptions (all multiples of 4, listed because they are fixed dimensions, not scale steps):
- Touch targets: inputs, buttons, checkbox row min-height 44px (`min-h-11`); primary submit 56px (`min-h-14`, as review page). Checkbox hit area 44x44 via padded label; visible box 20px.
- WhatsApp clearance on mobile: sheet bottom offset 88px (button 56px + 16px offset + 16px gap).
- Pop-up desktop width 480px (`max-w-120`); mobile sheet max height 35vh.

| Role | Size | Weight | Line Height | Font |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--gc-void` #0D1F17 | Page background, footer inner area, pop-up and sheet overlay surface on public pages |
| Secondary (30%) | `--gc-jungle` #0C3C2D (dark surfaces: footer band, pop-up, sheet); `--gc-parchment` #F5EEDA (light card on utility pages `/newsletter`, `/wifi`, confirm, unsubscribe, matching `/review`) | Cards, footer, pop-up |
| Accent (10%) | `--gc-gold` #C69B3C | See reserved list |
| Destructive | #B3402A on parchment (error text and border only); #E8836B on jungle/void | Form errors only. No destructive action exists in this phase; unsubscribe is neutral, not red |

Text: on dark surfaces `--gc-ivory` (secondary text `text-gc-ivory/70`); on parchment `--gc-text-dark`, secondary `--gc-text-mid`. Primary button: dark variant `bg-gc-gold text-gc-void hover:bg-gc-brass`; light variant `bg-gc-jungle text-gc-ivory hover:bg-gc-void` (same as review `primaryClass`).

Accent reserved for: (1) the primary submit button fill on dark surfaces (footer, pop-up, sheet), (2) focus rings and focus outlines, (3) the 1px top border and corner brackets of cards, (4) the thin divider rule under the card eyebrow, (5) the checked state of the consent checkbox. Never for body text, links in body copy, or the WiFi password.

Contrast: gold #C69B3C on void passes AA for 14px/500 button text only because button text is void on gold (about 7:1); do not set gold text at 14px on parchment.

## Layout and Interaction Contract

### 1. Footer sign-up (D-10)
- Placed in `SiteFooter` above the existing copyright row, inside `max-w-5xl`, separated by a `border-t border-gc-gold/10` and `py-8`. Footer stays a Server Component; `NewsletterForm` is a client island.
- Desktop (md+): two columns, left = Heading 20px title + Body 17px one-line pitch; right = form. Mobile: stacked.
- Form fields in order: email (type=email, autocomplete=email, label visible, 44px high, `bg-transparent border border-gc-ivory/30`, placeholder never replaces label); language is not asked as a field, it is taken from the page locale (D-16) and shown in the consent line only; consent checkbox (unchecked by default, required, `required` + `aria-required`); optional resident checkbox "J'habite à Krabi" (footer and pop-up omit it: `showResident=false`; only `/newsletter` and `/wifi` show it); submit button.
- Consent text (Label 14px) contains a link to `/privacy` (opens same tab, underline).
- Honeypot field (visually hidden, `aria-hidden`, `tabIndex=-1`) and hidden `started_at` for fill-time check.

### 2. Pop-up (D-11)
- Triggers: desktop (pointer: fine) = `mouseleave` toward top of viewport (`clientY <= 0`) after 10 s minimum on page; mobile = after 45 s or 60% scroll, whichever first. One per visitor: localStorage key `gc_nl_popup` storing `{state: 'dismissed'|'subscribed', until: now+90d}`. Never on `/review`, admin, reservation funnel, `/newsletter`, `/wifi`, confirm, unsubscribe. Never while the reservation form has focus.
- Desktop: centered dialog, `role="dialog"`, `aria-modal="false"` is NOT used; use `aria-modal="true"` with a `bg-gc-void/70` backdrop, focus trapped, Escape closes, backdrop click closes, focus returns to previously focused element. Width 480px max, `bg-gc-jungle`, 1px `border-gc-gold/20`, 2px gold top border (matches `.gc-card-pilier`), padding 32px (xl). Close button top-right, 44x44 hit area, `aria-label` from i18n.
- Mobile: non-modal bottom sheet. `role="region"` with `aria-label`, `aria-modal` absent, no backdrop, page remains scrollable and interactive, no focus trap. Fixed `inset-x-2` (8px), `bottom: 88px` (clear of WhatsApp button, which stays visible and tappable), `max-height: 35vh` with `overflow-y: auto`, `bg-gc-jungle`, 2px gold top border, padding 16px. Content: Heading 20px (one line, truncation not allowed, wrap to two), one email input, consent checkbox, submit; close button 44x44 top-right. z-index below the WhatsApp button (`z-30` vs button `z-40`). If the on-screen keyboard opens, sheet may scroll internally; it must not cover the focused input (`scrollIntoView({block:'nearest'})`).
- Animation: sheet slides up 16px and fades in over 300ms ease; dialog fades in 200ms. Both disabled by the existing reduced-motion rule.
- Closing (X, Escape, backdrop) sets state `dismissed`. Successful submit sets `subscribed`. Pop-up never reopens within 90 days.
- Measurement: client posts an anonymous `shown` / `dismissed` event with `source=popup` to the events endpoint (no PII); `submitted` counted server-side on subscribe.

### 3. `/newsletter` landing (D-12)
- Layout identical to `/review`: `main.bg-gc-void`, `pt-16 pb-24 sm:pb-16 px-4`, centered `max-w-md` parchment card with four gold corner brackets, eyebrow "Gecko Cabane" (Raleway 14px uppercase), gold divider (40px x 1px), h1.
- Display 28px h1 (sm+) / Heading 20px (mobile); Body 17px pitch naming the offer ("recette du curry de crabe de la cheffe Jariya"); a recipe teaser line (Label 14px italic) stating the recipe arrives by email after confirmation. No image of the recipe is shown before confirmation (the gate is double opt-in, no placeholder photo unless the owner supplies one).
- `NewsletterForm variant=light showResident` below. After submit the form is replaced by the "check your inbox" state (see states). Header and footer chrome: no site nav, no `SiteFooter` form (avoid a duplicate form on the same page); keep `WhatsAppButton`.
- Meta: noindex, no sitemap entry, no hreflang; `?src=qr` sets source `bill_qr`; missing or other `src` defaults to `footer`-equivalent `newsletter_page`.

### 4. `/wifi` (D-13)
- Same parchment card shell. Order top to bottom: eyebrow, divider, h1 (Heading 20px), then immediately the credentials block (no gate, above the fold on a 667px-high phone): "Network" label (Label 14px) + network name (Body 17px weight 500); "Password" label + password (Body 17px weight 500, `select-all`, `font-mono`-style spacing), with a "Copy password" secondary button (44px min) that copies via `navigator.clipboard` and shows an inline "Copied" confirmation (`aria-live="polite"`) for 2 s. Credentials block: `bg-gc-aged/50 border border-gc-aged p-4`.
- Below, separated by a `border-t border-gc-aged` and 32px gap: optional sign-up section with a Heading 20px title, one line stating it is optional and not needed for WiFi, then `NewsletterForm variant=light showResident`.
- Credentials come from env on the server; the page is `dynamic`, `noindex`, `Cache-Control: no-store`. If the env var is missing, render the "WiFi unavailable" state (below) rather than an empty field.

### 5. Confirm page (`/{locale}/newsletter/confirm?r=&s=`)
- GET renders parchment card with message and one primary button "Confirm my subscription". No state change on GET. The button submits a `<form method="post">` (progressive) or `fetch` POST to `/api/newsletter/confirm`; button disabled and label changes to "Confirming..." while pending (`aria-busy`).
- Result states replace the card body: success (Heading + Body + secondary link "Back to the site"; if source is `bill_qr`, a primary button/link "Get the crab curry recipe" is shown), already-confirmed (same as success, neutral wording), invalid or expired link (error state with a link back to the footer form).
- noindex.

### 6. Unsubscribe page (`/{locale}/newsletter/unsubscribe?r=&s=`)
- GET renders card with the email's masked form (`j***@gmail.com`) only if the signed token resolves; button "Unsubscribe" (secondary/outline style, not red, not gold) POSTs. Success state: confirmation that no further emails will be sent, PDPA B.E. 2562 / GDPR reference line (Label 14px), and a quiet "Changed your mind? Subscribe again" link to the footer form. Invalid link state offers contact by email.
- Brevo-hosted unsubscribe page is outside our control; our page only serves Resend-originated links (D-04).

### 7. Email templates (Resend, reuse `baseTemplate`)
- Width 600px max, single column, background `#FAF0E6` page, `#0C3C2D` header band with the Gecko Cabane wordmark, body Cormorant fallback stack `'Cormorant Garamond', Georgia, serif` 17px/1.5, `#1A0E00` text. Button: bulletproof table button, `#0C3C2D` fill, `#FAF0E6` text, 14px uppercase, min 48px high, full width on mobile. Gold `#C69B3C` only for a 1px divider.
- Confirmation email: subject, one-line explanation of why they received it, one button "Confirm my subscription" (link to confirm GET page), plain URL fallback under the button, line "If you did not ask for this, ignore this email; nothing will be sent." Link expires in 30 days (stated).
- Welcome email: thanks, Guide gourmand link (PDF, button), recipe button only when source is `bill_qr`, short sign-off from Chef Jariya. Footer on every newsletter-related Resend email: unsubscribe link (signed route), restaurant postal address (Maharat Road, Krabi Town), mention of PDPA B.E. 2562 and GDPR.
- Locales: FR and EN; `de` and `sv` render the EN template (D-02). Plain-text part required for every email.

## States

| State | Behavior |
|-------|----------|
| Idle | Submit enabled only when email is valid format and consent checked (otherwise button stays enabled but submission shows inline errors; do not disable silently) |
| Submitting | Button shows "Sending...", `aria-busy`, fields read-only |
| Success | Form replaced by confirmation panel with `role="status"`: "Check your inbox" heading + body. Same panel for new and already-subscribed emails (no enumeration). Pop-up auto-closes 6 s after success unless focus is inside it |
| Field error | Inline message under field in destructive color, `aria-describedby`, field border changes color (never color alone: prefix text "Error:" is not required but message must be text) |
| Server error | Panel-level message with retry (button re-enabled) |
| Rate-limited (429) | Server-error message variant asking to retry later |
| WiFi unavailable | Card shows "Ask a member of staff for the WiFi password" with no form removal (sign-up section still shown) |
| Reduced motion | No slide/fade; state changes are instant |

## Accessibility

- All inputs have programmatically associated visible labels; errors via `aria-describedby`, announced in a `role="alert"` region; success via `role="status"`.
- Keyboard: tab order matches visual order; pop-up dialog (desktop) traps focus and restores it; mobile sheet does not trap focus and is reachable in DOM order after main content landmarks (appended at end of body).
- Focus ring: existing global 1px gold outline with 2px offset; on parchment use gold ring offset parchment (as review buttons).
- Touch targets 44px minimum; contrast AA for all text pairs listed under Color.
- Language: `lang` attribute follows locale; DE/SV fall back to EN copy so set `lang="en"` on translated fallbacks only if text is rendered in EN.
- Pop-up must never block the WhatsApp button, reservation CTA, or page scrolling on mobile.
